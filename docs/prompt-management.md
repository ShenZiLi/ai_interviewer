# 风格偏好与提示词管理

## 已确认的权限边界

普通用户选择风格，不编辑提示词；管理员在独立 Web 后台维护全部十类任务模板。用户自定义 API 与管理员提示词管理是两项不同能力。生产环境必须进行服务端权限验证，原型顶部入口仅用于切换视角。

## 任务模板目录

| 编号 | 任务 | 主要触发点 |
| --- | --- | --- |
| P01 | 简历理解 | 导入简历 |
| P02 | 目标岗位分析 | 确认岗位或 JD |
| P03 | 需求澄清与方向推荐 | 准备阶段对话 |
| P04 | 面试大纲规划 | 用户确认偏好 |
| P05 | 自我介绍后大纲调整 | 自我介绍提交 |
| P06 | 当前主问题生成 | 开始新问题 |
| P07 | 回答评价 | 每轮回答提交 |
| P08 | 追问决策与生成 | 当前回答分析后 |
| P09 | 辅导与答案优化 | 陪练反馈或复盘 |
| P10 | 整场复盘报告 | 整场结束 |

任务不等同于独立请求。岗位分析与方向推荐、规划与主问题草案、评分与优化建议可以按延迟和质量要求组合，具体调用边界由架构阶段确定。

## 原型风格选项

- 面试官表达：温和鼓励、专业中立、简洁直接。
- 考察倾向：均衡考察、基础原理优先、项目深挖、业务场景优先。
- 追问策略：逐步引导、标准递进、深入挑战。
- 反馈详略：简明要点、详细分析。

提供基础巩固、标准面试、项目深挖快捷组合。该组选项文案是待评审原型细节。考察倾向先用单选主倾向演示，主次组合的细化未实现。

默认偏好与本场配置分开。风格不影响评分标准；模拟模式不因风格而展示提示或评分。

## 发布与追溯

任务模板采用草稿、测试、发布流程。草稿再次编辑后应重新测试。回滚创建新版本并保留来源版本。开始面试时锁定模板版本和风格配置；真实产品还需锁定量表、风格规则及其他影响判断的配置版本。

管理员管理范围还包括风格规则映射与评价量表。本轮原型先演示任务模板编辑和版本生命周期，规则映射与量表编辑界面后续细化。

## 原型限制

所有状态仅存于页面内存。示例测试仅检查非空草稿和操作顺序，不调用 LLM，不验证语义质量。发布和回滚只是本页演示，不影响真实用户。面试题目和报告仍为预置内容，不受编辑后模板或风格驱动。

## 后续技术设计需明确

管理员初始化与授权方式、测试用例集与通过条件、输出结构、版本发布粒度、并发编辑与审计存储、提示词变量的安全注入方式。

## 原型验证记录

- app.js 与 prompts.js 均通过 Node 语法检查。
- 浏览器验证草稿保存、示例测试、发布 v2、回滚生成 v3。
- 已通过演示测试的草稿再次修改后，发布按钮重新禁用。
- 开始面试锁定 P08 v1 后发布 v2，管理页仍显示本场使用 v1。
- 设置页选择基础巩固后进入准备页，正确显示温和鼓励、基础原理优先、逐步引导和详细分析。
- 检查 Web 管理页三栏与手机尺寸风格设置布局。
