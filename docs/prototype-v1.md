# 第一版 UI 原型范围

## 已确认的设计依据

专业简洁、浅色。Web 与微信小程序共用六页信息架构。准备流程采用对话与选择卡片结合；面试室突出当前问题、手动语音轮次及阶段进度。

## 本轮制作顺序

1. 创建无需安装依赖的 HTML、CSS、JavaScript 本地交互原型。
2. 使用虚构订单项目串联简历确认、岗位准备、技术方向多选、流程预览。
3. 演示陪练与模拟两种模式、回答状态、单轮反馈及自我介绍后的大纲调整。
4. 补齐工作台、报告、设置页面，并提供手机尺寸预览。
5. 检查脚本语法、浏览器交互和两端布局，修复问题后本地提交。

## 文件职责

- prototype/index.html：原型入口与页面容器。
- prototype/styles.css：视觉规范和 Web / 手机响应式布局。
- prototype/app.js：示例数据、页面渲染及演示交互。

## 演示边界

不读取上传文件内容、不调用 API、不录音、不保存密钥、不实现登录或微信 SDK。上传、解析、评分、语音与模型连接仅展示交互方案，界面明确标注。刷新会重置演示状态。

手机预览用于评审微信小程序布局，不能据此认定已完成真机或小程序兼容验证。架构图与技术选型在 UI 核心流程评审后继续推进。

## 本轮验证记录

- `node --check prototype/app.js`：通过语法检查。
- 浏览器验证 Web 三栏面试室及手机预览的单列布局。
- 验证方向多选结果进入流程预览。
- 验证陪练手动开始/提交、每轮反馈、自我介绍大纲确认及继续按钮。
- 验证模拟模式自动更新大纲且不展示即时评分。
- 390 × 844 浏览器视口检查简历、准备、流程、设置和报告；检查的页面未出现横向溢出。
- 验证自定义厂商表单与连接测试的演示提示。
- 发现提示条遮挡手机导航点击，修改为不拦截指针事件；复测提示出现时能够进入报告。

## 原型待评审重点

1. 准备页的信息量与对话式选择体验。
2. 面试室的流程、问答、反馈三者优先级。
3. 手机端回答结束后的反馈阅读与继续操作是否顺畅。
4. 陪练每轮反馈的粒度，以及报告八维评价是否容易理解。

本轮没有接入或测试真实厂商 API、语音延迟、真实文件解析、小程序 SDK 或账号数据同步。
