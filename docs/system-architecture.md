2. **文本 LLM 选择**：为现有主流厂商（GLM / Qwen / DeepSeek）提供**预设选择，自动带出配置**，同时**保留用户自定义 API（自备 key）**。

## 1. 目标与约束

产品：实时语音问答面试训练，一期面向 Java 后端求职者，**电脑 Web + 微信小程序双端、必须登录、共用账号与数据**。

交互关键约束（来自需求与原型）：
- 一期只做语音问答，**用户手动控制每问开始/结束**（按轮次，非连续自由对话）。
- 需要 P01—P10 提示词编排、结构化输出（评分、大纲、追问等均为 JSON）。
- 双端体验：Web 三栏面试室；小程序单列问答、底部语音操作。

双端对实时语音的承载能力差异很大，直接决定链路取向（见 §2）。

## 2. 核心链路取向

存在两种语音链路，取舍不同：

| 取向 | 说明 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. 级联（推荐为主）** | ASR（识音）→ 文本 LLM（编排/生成）→ TTS（播报），由服务端串联 | 双端通用、可控、每段可结构化输出（P01—P10）；DeepSeek 可当低成本文本 LLM；便于评测/审计 | 流程多一步，端到端延迟略高（取决于 ASR/TTS 是否流式） |
| **B. 端到端实时**（GLM-Realtime / Qwen-Omni-Realtime） | 一次 WS/WebRTC 连接完成 ASR+LLM+TTS | 延迟低、实现简单 | 上下文小（如 qwen-omni 32K）；部分不支持函数调用/结构化输出；成本通常更高（音频 token 计价）；小程序长连与双端一致性受限 |

**建议**：
- 以**级联链路为基线**，因为它与「手动分轮、结构化编排、双端一致」的既定产品约束最匹配，且能打通无语音能力的 DeepSeek（作为文本 LLM 降本）。
- **Web 端**可后续试点端到端 Realtime 通道做低延迟增强；**小程序端不依赖**实时长连，以「分段录制上传」为主要输入方式。
- 是否开放端到端实时作为增强，列入待决策（§8）。**此取向建立在小程序无 WebRTC、WS 受限、录音单次 ≤10 分钟等官方约束上**。

## 3. 系统架构（分层）

```
┌───────────────────────────────┐   ┌───────────────────────────────┐
│       电脑 Web（SPA）          │   │       微信小程序               │
│   · 语音：原生 getUserMedia +   │   │   · 录音 RecorderManager       │
│     MediaRecorder / 可 WS 流     │   │     (mp3/aac，单次≤10min)     │
│   · 登录：账号密码/短信           │   │   · 登录：wx.login+code2Session│
└───────────────┬───────────────┘   └───────────────┬───────────────┘
                │  HTTPS / wss(可视需要)              │  HTTPS / wss（域名白名单，ICP备案）
┌───────────────▼───────────────────────────────────▼───────────────┐
│                           应用服务器（核心）                         │
│  · 账号与会话（跨端统一）           · 面试状态机（按轮编排 P01—P10）    │
│  · 提示词模板库+版本锁定/回滚       · 上下文/大纲/追问组织              │

└───────────────┬─────────────────────────────────────┬────────────┘
        ┌───────▼────────┐            ┌────────────────▼─────────────┐
        │  语音服务网关     │            │  模型编排层（Model Layer）     │
        │  ASR 路由 + TTS   │            │  依能力矩阵路由到供应商         │
        │  路由（见§5）     │            │  文本 LLM · 结构化输出 · 函数调用│
        └───────┬────────┘            └───────────────┬──────────────┘
                └───────────────┬───────────────────────┘
                    ┌───────────▼────────────┐     ┌──────────────────┐
                    │ 第三方能力（按接入）       │     │  持久化           │
                    │ 智谱GLM / 阿里qwen /      │     │  面试转写·评价     │
                    │ DeepSeek / 小程序CDN等    │     │  配置版本·用户数据  │
                    └─────────────────────────┘     └──────────────────┘
```

**关键设计点**：
- 状态机在服务端：P01—P10 提示词的「组合请求 → 结构化输出 → 状态推进」都由服务端完成，保证双端一致与新面试锁定版本。
- 语音网关解耦供应商：ASR/TTS 可独立切换（GLM/阿里互备），文本 LLM 亦可独立路由（如 DeepSeek 低成本、GLM/Qwen 通用），互不绑定。
- 鉴权与服务端权限：管理员入口由服务端校验（原型顶部入口仅演示）。

## 4. 一次回答的时序（级联基线，Web 与小程序统一）

1. 用户点击「开始作答」→ 客户端开始录音（Web：MediaRecorder；小程序：RecorderManager）。
2. 用户点击「作答完成」或到时 → 客户端上传/传送一段音频（小程序为 mp3/aac 文件上传；Web 可整段上传或 WS 推流）。
3. 应用服务器调用 ASR，得该段转写文本。
4. 文本 LLM 依 P07 模板结合上下文、简历、大纲、风格规则生成**结构化评价 JSON**（模拟模式进入整场统一评价，不在此展示）。
5. 主问题/追问阶段：LLM 依 P06/P08 生成下一问文本，TTS 合成音频回传（Web auiode、小程序 innerAudioContext 播放 https 音频 URL）。
6. 记录转写、评分、证据；按 §需求默认保存转写与评价，录音是否保留由用户选择。

> Web 可选：若启用端到端 Realtime（§2-B），此时序替换为单条 WS 长连，但结构化编排与双端一致需另行验证。

## 5. 技术选型对照表（能力矩阵，官方依据见 §9）

### 5.1 语音能力

| 能力 | 智谱 GLM | 阿里 通义/百炼 | DeepSeek |
| --- | --- | --- | --- |
| 实时 ASR | 有（GLM-ASR-2512，HTTP SSE 流式，中文+方言/多语；≤25MB ≤30s） | 有（Paraformer 实时，**WebSocket**，`paraformer-realtime-v2`；中文+方言，自动断句标点；0.00024 元/秒） | **无** |
| TTS | 有（GLM-TTS，流式+非流式，首帧<400ms，2 元/万字；另有音色克隆） | 有（CosyVoice v3.5-flash，**WebSocket 实时**，0.8 元/万字） | **无** |
| 端到端实时语音 | 有（GLM-Realtime，WS 一次连接，支持函数调用/打断，音频 0.18~0.3 元/分） | 有（Qwen-Omni-Realtime，WebSocket/WebRTC；`qwen-omni-turbo-realtime` 上下文仅 32K，**不支持函数调用与结构化输出**） | 无 |
| 备注 | ASR 仅 HTTP SSE（无独立 WS ASR） | Omni Realtime 不具函数调用/结构化输出 | 仅文本/视觉 |

### 5.2 文本 LLM（编排/生成层）

| 项 | 智谱 GLM | 阿里 qwen | DeepSeek |
| --- | --- | --- | --- |
| 代表模型 | GLM-5.3 / FLash（1M 上下文） | qwen-plus / qwen3.7（1M） | deepseek-flash / v4-pro（1M） |
| 结构化输出(JSON) | 支持 | 支持 | 支持 |
| 函数调用(tools) | 支持（含 Realtime） | 支持（含内置工具） | 支持 |
| 成本(约) | GLM-5.3-Flash 输入 0.8 元/M | qwen-plus 输入 0.8 元/M | deepseek-flash 输入 1 元/M、输出 2 元/M |
| 兼容接口 | 自家协议 | 自家协议 | OpenAI / Anthropic 兼容 |

### 5.3 小程序端关键约束（官方）

- 登录：`wx.login`→code2Session 换 openid/session_key（session_key 禁止下发客户端）；手机号快捷验证组件需**非个人主体且认证**，0.03 元/次。
- 录音：`RecorderManager`，格式 mp3/aac/wav/PCM，单次 ≤10 分钟，**无后台录制**；支持 `onFrameRecorded` 分片回调（边录边传）。
- 网络：request/uploadFile/downloadFile 的域名须 https 且 **ICP 备案**（生产不可 IP/localhost）；ws 用 `wx.connectSocket` 且 **并发 ≤5**。
- 实时能力：**无标准 WebRTC**；`live-pusher/live-player` 仅**企业类小程序+限定类目**可开通。
- 体积：主包 ≤2M、总分包 ≤30M（语音 SDK 若打客户端会挤压预算，倾向服务端调用、客户端不内置大 SDK）。
- Web 端无法用 wx.login；可选微信开放平台网页扫码 OAuth 或自建账号体系（见 §8 待决策）。

## 6. 接口与数据模型草案（待评审）

以「面试（Interview）→ 轮/环节（Turn）→ 音频/转写/评价」为核心：

- `Interview`：id、userId、junior/mid/senior 档、模式(陪练/模拟)、风格配置快照、模板版本快照、方向列表、岗位/JD、大纲、状态。
- `Turn`：id、interviewId、环节(自我介绍/技术/业务/HR)、主问题、用户转写、TTS 音频引用、追问串、评价(评分＋证据＋建议)、录音保留标记、首次 vs 提示后表现。
- `PromptTemplate`：P01—P10 的草稿/测试/发布版本、上下文变量埋点、回滚来源、生效锁定场次。
- 语音网关接口（服务端内部）：`ASR(audio) → {text, confidence}`、`TTS(text, voice) → {audioUrl/流}`。
- 模型编排接口：`compose(turnContext, template, style) → {structuredJson}`。

> 具体字段、命名、版本锁定粒度和接口定义，在架构评审通过后在「接口规范」中细化。

## 7. 里程碑建议（待确认）

1. 本架构与选型评审通过。
2. 单端（Web）端到端最小闭环：简历解析 → P01—P10 单条主链 → 语音问答 → 反馈，先接一家供应商打通级联链路。
3. 小程序端接入登录 + 录音分段上传 + TTS 播放。
4. 提示词管理后台接入服务端权限与版本发布（草稿→测试→发布→回滚）。
5. 进行双端一致性、权限、安全与成本验收。
